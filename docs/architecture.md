реалізація.

процесу в цьому документі названо «конфігурацією».

## 5. Правило залежностей

```text
web, api ──► auth ──► storage
web, api ──► services ──► storage
update ──► services, storage
logging, clock — може використовувати будь-який компонент
config — читається лише під час старту
```

- `web` і `api` звертаються до `services` і `auth`; до `storage` напряму не ходять.
- `auth` стоїть на рівні `services`: `web` і `api` → `auth` → `storage`.
- `services` не знає про HTTP: не залежить від `web`, `api` і FastAPI.
- `update` використовує `services` і `storage`. `services` від `update` не залежить.
- `logging` і `clock` може використовувати будь-який компонент.
- `config` читається лише під час старту, під час збирання застосунку. Значення конфігурації
  передаються компонентам параметрами; напряму `config` жоден компонент не імпортує.
- `src/spm` не імпортує `/simulator` (REQ-NF-029).

**Ручний запуск** (REQ-F-020, REQ-F-021) починається з `web` чи `api`, а виконує його `update`.
Щоб не було залежності `services` → `update` (і циклу), `services` задає порт «запустити
оновлення», а `update` його реалізує. Реалізацію підключають до `services` під час старту, там
само, де читається `config`. Залежність лишається одна: `update` → `services`.

`web` і `api` викликають ті самі функції `services` і `auth`. Тому екран і операція API дають ту
саму поведінку (REQ-NF-031).

## 6. Журнали й ідентифікатор запиту

- Middleware `logging` на початку кожного HTTP-запиту створює ідентифікатор запиту. Після
  відповіді він пише запис HTTP-запиту: метод, шлях без рядка запиту, код, тривалість, логін
  (REQ-NF-032).
- Записи журналу дій і технічного журналу, зроблені в межах запиту, отримують цей ідентифікатор;
  у відповідь він не повертається (Р-126).
- Записи запусків мають поле id запуску. У ручному запуску ідентифікатор запиту — ідентифікатор
  запиту, що почав запуск. У запуску за розкладом і доганянні — id запуску (REQ-NF-032).
- Збій запису в будь-який журнал не змінює ні дії, ні відповіді (REQ-NF-033).
- Час записів береться з `clock`, зі зсувом київського часу (Р-126).
