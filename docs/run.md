# Встановлення, налаштування і запуск

Інструкція T-46 (REQ-F-006, REQ-NF-009, REQ-NF-014, REQ-NF-022, REQ-NF-028). Усі команди
виконуються з кореня репозиторію, якщо не сказано інше. Команди перевірено 2026-11-18 на Windows 11
з Python 3.12 (`logs/2026-11-18-verification-gaps.md`). У тексті немає паролів і секретів: їх
кожен задає сам.

## 1. Встановлення

Потрібні Python 3.12 і, лише для контрактного прогону проти mock, Node.js з npm.

Віртуальне середовище і залежності (разом з інструментами розробки pytest, ruff, pytest-cov):

```powershell
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install -e ".[dev]"
```

У Linux / macOS: `python3.12 -m venv .venv` і `source .venv/bin/activate`, далі та сама команда
`pip`. Пакет встановлюється в режимі редагування, тож зміни в `src/` діють без перевстановлення.

## 2. Конфігурація

Система читає параметри зі змінних середовища або з файлу `.env` у робочому каталозі (файл
внесено до `.gitignore`, у репозиторій він не потрапляє). Змінна середовища має пріоритет над
файлом.

| Параметр | Обов'язковий | Що задає | Типове значення |
|---|---|---|---|
| `SPM_SESSION_SECRET` | так | ключ підпису сесії | — |
| `SPM_DATABASE_PATH` | ні | файл бази SQLite | `var/spm.db` |
| `SPM_ACTION_LOG_PATH` | ні | файл журналу дій | `var/actions.log` |
| `SPM_TECHNICAL_LOG_PATH` | ні | файл технічного журналу | `var/technical.log` |

Без `SPM_SESSION_SECRET` система не стартує і пише, якого параметра бракує (REQ-NF-022). Ключ —
довгий випадковий рядок; згенерувати його можна так:

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
```

Приклад `.env` (значення ключа — своє):

```text
SPM_SESSION_SECRET=<згенерований ключ>
```

Відносні шляхи рахуються від робочого каталогу, тому систему й команди запускають з кореня
репозиторію. Каталог `var/` теж у `.gitignore`.

## 3. Облікові записи

Облікові записи створює лише команда початкового налаштування (REQ-F-006); у вебінтерфейсі й API
такої дії немає:

```powershell
python -m spm.auth.cli <логін> admin
python -m spm.auth.cli <логін> manager
```

- Логін: латинські літери, цифри, крапка, підкреслення, дефіс; 3…32 символи. Логін, що вже є
  (без огляду на регістр), команда відхиляє.
- Пароль команда запитує інтерактивно двічі («Пароль:», «Повторіть пароль:»); у параметрах
  команди його немає. Не менше 8 символів.
- Команда читає ту саму конфігурацію (`.env`), тож створює запис у тій самій базі, з якою
  працюватиме система. Створення записується в журнал дій.
- Довідка: `python -m spm.auth.cli --help`.

## 4. Імітатор постачальників

Імітатор — окремий застосунок у `simulator/` (REQ-NF-029). Запуск в окремому терміналі:

```powershell
python -m simulator
```

Без параметрів він слухає `127.0.0.1:8001` і віддає дані з `simulator/data.json`; порт і файл
даних можна задати: `python -m simulator 8002 шлях/до/data.json`. Сторінки каталогів:

| Постачальник | Адреса каталогу | Розбирач |
|---|---|---|
| Альфа Плита | `http://127.0.0.1:8001/catalog/alfa` | `table_layout` |
| Бета Кромка | `http://127.0.0.1:8001/catalog/beta` | `cards_layout` |
| Вега Фурнітура | `http://127.0.0.1:8001/catalog/vega` | `list_layout` |

Ці адреси й розбирачі адміністратор вказує на екрані «постачальники». Файл даних читається на
кожен запит, тож зміни цін, асортименту й режиму діють з наступного запиту без перезапуску
(REQ-NF-027). Режим кожного постачальника — поле `mode` (REQ-NF-028):

| `mode` | Що робить імітатор |
|---|---|
| `normal` | звичайна сторінка |
| `unavailable` | відповідь 503 |
| `slow` | відповідь із затримкою `delay_seconds` секунд (у файлі — 35 с, більше за таймаут отримання сторінки 30 с, REQ-F-026) |
| `reduced` | лише перші `keep_items` позицій |
| `broken` | сторінка зі зміненою розміткою, яку жоден розбирач не знає |

## 5. Запуск системи

Одна команда (REQ-NF-014), з кореня репозиторію:

```powershell
uvicorn spm.app:create_service --factory --no-access-log
```

Система слухає `http://127.0.0.1:8000` (інший порт — `--port 8010`): вебінтерфейс — `/`, вхід —
`/login`, REST API — `/api/v1` за контрактом `spec/openapi.yaml`. Ця команда вмикає планувальник
(щоденний запуск оновлення в заданий час) і одразу після старту виконує доганяння, якщо запуск
дня пропущено (REQ-F-018, REQ-F-023). `--no-access-log` вимикає власний журнал запитів uvicorn:
запити пише журнал дій системи (REQ-NF-032).

Зупинка — Ctrl+C. Запуск, що виконувався в момент зупинки, у журналі оновлень стане «перервано»,
і після наступного старту система доганяє день (REQ-F-024).

## 6. База і журнали

За типових параметрів усе лежить у `var/` робочого каталогу:

| Файл | Що в ньому |
|---|---|
| `var/spm.db` | база SQLite: довідники, позиції, прив'язки, ціни дня, стрічка змін, журнал оновлень, налаштування, облікові записи |
| `var/actions.log` | журнал дій: рядки JSON — запити, входи, зміни, відмови в доступі (REQ-NF-032) |
| `var/technical.log` | технічний журнал: рядки JSON — помилки і збої отримання сторінок (REQ-NF-018); з'являється з першим записом |

Обидва журнали — лише у файлах на сервері; на екранах і через API їх немає. Базу й файли
журналів система створює сама під час старту.

## 7. Тести

Звичайний прогін (усі тести, крім тестів швидкодії; без зовнішньої мережі, REQ-NF-013):

```powershell
python -m pytest
```

Покриття коду:

```powershell
python -m pytest --cov=spm --cov-report=term
```

Тести швидкодії REQ-NF-008 і REQ-NF-009 (T-45) мають мітку `performance`, у звичайний прогін не
входять і запускаються окремою командою. Ключ `-s` показує рядки `PERFORMANCE` з виміряними
значеннями й характеристиками машини для протоколу:

```powershell
python -m pytest -m performance -s tests/test_performance.py
```

Тест REQ-NF-009 генерує тестовий обсяг (1 000 матеріалів, 10 постачальників, ціни дня за рік —
3,65 млн рядків, 10 000 подій) у тимчасовому каталозі pytest (база — близько 230 МБ); генерація і вимір тривають близько 15 с.

Стиль коду (REQ-NF-025):

```powershell
ruff format --check src simulator tests
ruff check src simulator tests
```

## 8. Контрактний прогін

Сценарії `tests/contract/scenarios.json` (86) перевіряють відповідність контракту
`spec/openapi.yaml`; опис — `docs/api/scenarios.md`.

**Проти mock** (Prism, з контракту). Один раз встановити інструменти Node:

```powershell
npm install
```

Далі в одному терміналі mock на порту 4010, у другому — прогін:

```powershell
npx prism mock -p 4010 spec/openapi.yaml
```

```powershell
python tests/contract/run_mock_scenarios.py
```

Очікуваний результат: 85 пройдено, 1 пропущено (Н-27 mock не відтворює).

**Проти сервера.** Скрипт сам створює дані, облікові записи, запускає імітатор і систему і
зупиняє їх наприкінці; порти 8000 і 8831 мають бути вільні:

```powershell
python tests/contract/server_run.py <мітка>
```

Результати — у `var/contract-<мітка>/results.json` (каталог з такою міткою не має існувати
заздалегідь). Очікуваний результат: 86 з 86.
